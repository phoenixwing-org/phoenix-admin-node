# 开发插件初始化与就绪检测

## 边界

Hub 的 `mounted` 只证明 Node/Vue 开发源码已挂载，不代表插件已经 Pah 登记、安装、启用或物化到 Ribbon。Pah Node 是 manifest、DDL、迁移台账、菜单贡献和权限的唯一权威；Vue 只展示服务端结论并触发已有受控生命周期。

Host 不从产品源码目录直接登记 manifest。管理员必须选择当前产品生成的不可变 `.phoenix.cool` 包；安装器先校验包身份、manifest v2、integrity 清单、迁移 SHA 和 Node/Vue payload。开发 symlink 只在 `NODE_ENV=local` 且双端 payload 与包内字节完全一致时可复用；正式环境仍只接受 Host 管理的普通目录。

## 检测接口

`GET /admin/phoenix/plugin/development-status` 合并以下证据：

- Node/Vue 开发 symlink 是否指向同一个 clean Git 产品 payload；
- Pah 安装记录、manifest 版本与生命周期状态；
- manifest 迁移与 applied ledger 的差集；
- `pah_plugin_menu_contribution` 与实际 Cool 菜单是否一一存在；
- 稳定 `plugin:<moduleId>:<navigationModuleId>` 分组 assignment 是否存在；
- 当前用户实际获授的可见路由；
- API 启动时写入的快照是否已加载当前版本和激活收据。

返回的就绪状态是幂等的：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `mounted-unregistered` | 已挂载，Pah 无记录 | 选择匹配的不可变包 |
| `mounted-version-mismatch` | 挂载 manifest 与台账版本不同 | 受控重登记 |
| `registered-not-installed` | 已验证/登记，未完成安装 | dry-run 后受控安装 |
| `installed-not-enabled` | 已安装或已停用 | 受控启用 |
| `enabled-contributions-missing` | 菜单、路由或 assignment 缺失 | 停用→启用受控重物化 |
| `enabled-restart-required` | 台账和贡献已就绪，当前进程尚未加载 | 在 Hub 重启 API/Web |
| `enabled-permission-filtered` | Ribbon 已物化，当前角色未授予全部路由 | 管理员配置角色权限 |
| `ready` | 挂载、台账、贡献、权限和启动快照一致 | 无 |
| `quarantined` | 挂载、身份或完整性不可信 | 修复产品包/挂载，不执行生命周期 |

接口不返回产品本机绝对路径，也不调用 Hub 的装配 API。

## 受控初始化

1. `POST /admin/phoenix/plugin/package` 权威验包，并将与包逐字节一致的本地挂载记为 development activation candidate。
2. `GET /admin/phoenix/plugin/migration-plan` 生成短时、一次性 dry-run。
3. `POST /admin/phoenix/plugin/local-controlled-install` 在有 pending DDL 时强制创建 `pg_dump` 备份并完成 `pg_restore` 演练，校验备份证明后才在单一事务执行 SQL 和写 ledger；无迁移也经过同一状态机。
4. `POST /admin/phoenix/plugin/enable` 物化菜单、capability 和 Ribbon 投影。首次 assignment 统一进入 Host 内置“业务”分组；已有管理员 assignment 不被覆盖，Host 不自动创建产品大组。
5. `activationMode=restart` 时，界面只打开 Hub，不跨域伪造重启成功。Hub 完成受控重启后，再用检测接口确认新进程快照。

禁止启用 TypeORM `synchronize` / Host `initialize`，禁止直接建表或伪造 applied ledger，禁止把产品 ID、源码路径或分组映射写进 Host tracked tree。
