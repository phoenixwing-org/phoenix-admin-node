# Phoenix Admin Node 0.2.2 发布说明

## 发布定位

`0.2.2` 是 `0.2.1` 之后的向后兼容补丁版本，继续兼容 Cool Admin Midway `8.x`
基线。本次收口 Phoenix 业务插件本机安装器：简化安装阶段、支持清理尚未安装的候选制品，
并提供不会与插件装配写入互相触发的稳定安装器运行模式。

## 插件安装

- `.phoenix.cool` 包仍必须自包含 Node/Vue 运行闭包，不执行插件提供的任意命令；
- 已验证但尚未安装的候选可以安全移除，再选择同一插件的新制品；
- 清理只移动本机候选 payload 并结束本次验证，不执行 SQL，不删除业务数据、迁移台账或
  管理员分组；任一步失败时恢复 Node/Vue 两侧候选目录；
- 拒绝不安全 module ID、symlink 以及非普通目录 payload；
- 新增 `pnpm dev:plugin-installer`：先完成完整 production build，再以显式受控本机安装
  Profile 启动；脚本固定关闭 `synchronize` 与初始化，避免 `mwtsc --watch` 因插件装配
  写入而并发清理 `dist` 并退出；
- production 默认仍拒绝本机包上传；只有同时设置
  `PAH_LOCAL_PACKAGE_MODE=true`、`PAH_DB_SYNCHRONIZE=false` 和
  `PAH_DB_INITIALIZE=false` 才允许该受控 Profile。

## 运行边界

- 新 Controller、Service、Entity 和任务进入当前进程前仍需要完整构建与 API 重启；
- 安装器不接收 shell、cwd、端口或任意 `pnpm` 参数；
- 生产受控重启应由 Dev Hub/systemd/容器编排等外部 supervisor 执行，API 进程不负责
  杀死并重新拉起自己；
- 运行时热加载仍是后续研究项，本版本不承诺进程内卸载 Midway 路由、装饰器或 Entity。

## 验证范围

- 插件包校验、候选清理、双目录回滚、链接拒绝和受控 production Profile 有定向测试；
- TypeScript、完整测试和 production build 作为发布门禁；
- 不包含业务插件产品源码、产品 ID、产品表或产品迁移；
- 不创建 tag、不推送，由发布负责人完成稳定分支合并和正式发布。
