# Phoenix Admin Node 0.2.1 发布说明

## 发布定位

`0.2.1` 是 `0.2.0` 之后的向后兼容修复版本，继续兼容 Cool Admin Midway `8.x`
基线。本次只修正 Pah 本地可信备份的 PostgreSQL CLI 前置门禁和 Windows 配置体验，
不改变插件 manifest、迁移制品或数据库 schema。

## 修复内容

- 在任何备份写入前统一检查 `psql`、`pg_dump`、`pg_restore`、`createdb` 和 `dropdb`。
- 要求五个客户端的主版本与真实 PostgreSQL 服务端一致，拒绝跨主版本恢复演练。
- 支持 Windows 绝对 `PAH_POSTGRES_BIN`、含空格路径和 `.exe`；同时保留五个工具的
  独立配置入口。
- 工具缺失、版本错配和子进程失败只返回工具名、配置键或失败阶段，不回显绝对路径、
  数据库口令、完整命令或 `ENOENT` 堆栈。
- 可信备份成功结果以工具来源类型替代本机 `bin` 绝对路径。

## 验证证据

- R14：Windows `.exe` 五件套、含空格路径、缺失工具、版本错配和脱敏失败均有定向测试。
- R15：在本机一次性 PostgreSQL 16 集群与隔离 Host baseline 数据库完成 custom dump、
  `pg_restore --list`、一次性数据库真实恢复和清理，残留恢复库为 0。
- Pah 生命周期、Host baseline、配置和插件包定向门禁通过；完整 Jest 门禁通过。
- Windows 发布机仍须按 [Windows可信备份工具链](../Windows可信备份工具链.md) 复跑
  R14/R15，作为平台实机证据。

## 版本边界

- 这是缺陷修复，因此使用 patch 版本 `0.2.1`，不提升到 `0.3.0`。
- 不包含任何业务插件产品代码、产品 ID、产品表或数据库迁移。
- 不创建 tag、不推送；由发布负责人在合并稳定分支并完成 Windows 实机复检后决定发布。
