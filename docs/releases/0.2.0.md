# Phoenix Admin Node 0.2.0 发布说明

## 发布定位

`0.2.0` 是 Phoenix Admin Host 的第二个独立产品版本，继续兼容 Cool Admin Midway
`8.x` 基线。本次发布聚焦通用业务插件宿主、受控安装与数据库安全门禁，不包含尚未完成
生产联调的 Admin Console 第三方登录能力。

Git 发布标签沿用既有惯例使用 `v0.2.0`。本提交只准备 `develop`；合并 `master`、推送和
创建标签由发布负责人统一执行。

## 主要变化

- 完善 Pah manifest v2、编译期插件登记与稳定公共装配入口。
- 支持插件路由前缀、导航、菜单、角色授权、字典贡献和迁移台账。
- 建立 SQL migration checksum、dry-run、可信备份、恢复演练及受控安装门禁。
- 支持声明式 runtime artifact 校验与复制，拒绝路径逃逸、符号链接和哈希不一致制品。
- 完善 `.phoenix.cool` 插件包校验、运行时检查、停用和保留数据卸载流程。
- 提供绑定冻结 Git 对象和 SQL 哈希的 Admin Host 空库发布验收基线。
- 修正密码登录日志脱敏与刷新令牌缓存，继续保持既有密码登录流程。

## 本次不包含

- 飞书及其他第三方登录入口、回调、外部账号绑定和相关数据库迁移。
- 在线插件市场、生产运行时源码执行或无需重启的动态模块加载。
- 任一业务插件的产品源码、数据库表或产品 ID 特例。

## 发布门禁

发布前必须完成：

1. `package.json`、欢迎页和 Swagger 版本均为 `0.2.0`。
2. 当前源码、测试和配置不包含本次暂缓的飞书登录、外部身份实现或相关迁移制品。
3. `pnpm run verify` 通过。
4. Git 工作树干净，发布提交位于 `develop`。
5. Node 与 Vue 分别合并到各自 `master` 后，再在对应最终提交创建 annotated tag
   `v0.2.0`。

## 升级提示

- 生产环境继续保持 `synchronize=false`、`initialize=false`。
- Pah Host schema 只执行 descriptor 中声明且 SHA-256 匹配的迁移。
- 插件包含 DDL 时，普通安装继续拒绝；必须先完成 dry-run、可信备份和恢复演练，再由
  受控编译期安装入口执行。
- 业务插件首次进入“业务”分组；管理员已有导航分配在升级和重新启用时保持不变。
